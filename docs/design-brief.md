## 目标与交付边界

为个人求职者设计中文桌面网页版看板，使用户能快速看清各岗位当前进度、下一步行动及临近时间。借鉴 Jira 的横向阶段列、跨列拖动、卡片详情、搜索和筛选。

交付可编辑的 Figma 高保真设计，复用卡片、状态标签、表单等组件，并覆盖关键状态。以约 30 条并行求职记录为布局容量目标，使用明确虚构的示例数据。首版手工维护，仅设计电脑端；不要求可点击原型、运行中的网页或实现代码。

受 MCP 额度限制，当前另提供[本地预览](../design/index.html)和导出素材供审阅，使用方式见 [design/README.md](../design/README.md)。这些补充成果不替代上述 Figma 原生交付：SVG 包含可编辑文字与矢量，但不是 Figma 组件或自动布局，尚未实际验证 Figma 导入。

## 已确认的记录与阶段规则

- 一张卡代表一个具体岗位的一次申请。同公司不同岗位独立记录；同岗位新招聘批次重新申请，新建记录。
- 四列固定为投递、测评、面试、结果，表示当前环节。待反馈的卡片留在相应环节。
- 允许跳阶段、返回前一阶段以纠正记录，或从任意阶段进入结果；保留变更历史。
- 同次申请的多轮测评与面试保留在同一卡片，显示当前轮次，详情保留每轮时间、备注及结果。
- 测评包括在线测评、笔试和作业等非面谈考核。

| 阶段 | 阶段状态或结果 | 进入规则 |
| --- | --- | --- |
| 投递 | 待投递、已投递 | 新建默认待投递；允许先记录尚未提交的岗位 |
| 测评 | 待安排、待完成、待反馈 | 拖入时预填待安排，确认后保存 |
| 面试 | 待安排、待完成、待反馈 | 拖入时预填待安排，确认后保存；轮次属于当前申请 |
| 结果 | 收到 Offer、未通过、主动退出 | 必须明确结果类型；收到 Offer 另有待决定、已接受、已婉拒 |

收到 Offer 不等于接受；主动退出不同于招聘方判定未通过。长期无回复留在原阶段并显示等待时长，不自动转为未通过。

## 信息层级

| 位置 | 内容 |
| --- | --- |
| 看板卡片 | 公司、岗位、城市、阶段状态或轮次、当前下一步行动及日期；有需要时显示等待时长或时间提醒 |
| 居中详情弹窗 | 上述信息，以及投递日期、岗位链接、薪资、渠道、备注、轮次和变更历史；Offer 与归档记录使用同一居中弹窗形式 |
| 新建／编辑 | 公司和岗位为新建必填项；其余信息可后补；编辑已存在的记录 |
| 下一步行动 | 一项当前行动，日期类型为截止或预约，也可无日期；过去行动保留在时间线 |

## 已确认的关键交互

### 新建、详情与编辑

新建只必填公司与岗位，默认投递／待投递。点击卡片后，在屏幕中央弹出卡片信息，背景加遮罩；弹窗可以关闭，内容超出可见范围时在弹窗内滚动。详情包含编辑入口、当前行动、轮次与变更历史。Offer 与已归档记录的详情也采用相同的居中弹窗形式。不同岗位或新申请不通过覆盖旧记录来维护。

### 跨列拖动与更新进展

跨列拖动后打开简短进展更新面板，确认目标阶段状态及下一步行动，不再单列“处理当前行动”。选择进入待反馈时，保存会一并完成当前行动；其他状态预填并保留原行动信息。进入测评或面试预填待安排，进入结果必须选择结果类型。进入一个阶段不自动宣布上一轮完成；完成行动也不自动跳阶段。

拖动只改变阶段，列内卡片顺序始终遵循当前排序规则，不提供拖动自由排序。

### 行动、轮次与日期

每张卡突出一项当前下一步行动；上一项行动和过去轮次保留在时间线。截止与预约在文案及提醒上有明确区别：

- 截止时间已过且仍未完成：逾期。
- 预约时间已过但进展未更新：待更新，不直接判定缺席或失败。
- 无日期的行动也可保存。
- 页面内突出今天、本周和逾期事项。

### 搜索、筛选与排序

搜索公司或岗位；筛选城市、阶段状态和日期范围。列内默认按当前下一步行动日期升序，无日期置后；可切换最近更新排序。筛选无结果需有清楚的恢复入口。

### Offer 与归档

Offer 细分为待决定、已接受、已婉拒；待决定可以有答复期限，通过居中详情弹窗处理决定。结果记录由用户手动归档，不自动归档。默认看板隐藏已归档记录，通过已归档筛选查找，在同样的居中详情弹窗中恢复。归档与恢复不改写求职结果或 Offer 决定。

### 状态主题与关键信息

用户最新要求是加强不同状态详情的主题色，使关键信息更易区分。本轮采用以下配色作为具体设计实现，颜色按当前阶段或结果类型一致映射，不为每家公司随机换色。

| 当前阶段或结果 | 主题色 | 色值 |
| --- | --- | --- |
| 投递 | 蓝 | `#245dcc` |
| 测评 | 琥珀 | `#a65b08` |
| 面试 | 紫 | `#7542c5` |
| 收到 Offer | 绿 | `#157653` |
| 未通过 | 玫红 | `#a54465` |
| 主动退出 | 灰 | `#526174` |

主题贯穿详情顶部、浅色岗位概览、状态标签、行动区和关闭按钮；正文保持清楚可读。颜色与文字共同表达含义，并遵循以下规则：

- 待反馈保留所属阶段色，明确显示等待的反馈内容及等待天数。
- 截止逾期在日期处使用红橙提醒；预约已过但未更新在日期处使用琥珀提醒。提醒不覆盖整张详情的阶段或结果主题。
- 归档在原结果主题上叠加灰色横条，保留原求职结果和 Offer 决定，不能与主动退出混为一类。
- 绿色表示收到 Offer，不代替待决定、已接受、已婉拒的文字。已作出决定的 Offer 不再显示“答复期限：未设置”。
- 关闭详情的按钮与“标记完成”行动区分，关闭不会更改求职进展。

## 设计选择

本节为便于实施而采用的可调整设计判断，不是额外的用户承诺，也不再扩展访谈范围。

| 未指定细节 | 首版设计选择 |
| --- | --- |
| 桌面布局 | 以 1440px 宽桌面为基准，四列同屏；顶部工具区与列标题保持可辨识，卡片溢出经纵向滚动访问。详情位置遵循最新确认的居中弹窗规则，遮罩后仍可辨识看板背景 |
| 详情尺寸与滚动 | 弹窗与视口边缘留出间距，高度不超过可用视口；长内容在弹窗内纵向滚动，关闭入口保持容易找到 |
| 约 30 条记录的呈现 | 用有代表性的记录展示阶段、轮次、提醒和结果差异；允许滚动，不靠缩小正文让全部记录挤入首屏 |
| 新建与编辑形式 | 使用同一套表单字段与样式，通过标题、预填值和保存文案区分模式；详情提供编辑入口 |
| 拖动确认与取消 | 保存进展更新后提交阶段变更；取消时卡片回到原列，数据保持原样 |
| 行动维护 | 进展表单直接预填当前行动、日期类型与时间；普通状态更新不宣称行动已完成。进入待反馈时明确提示保存将完成当前行动，隐藏行动输入，轮次仍独立保留。切回其他状态恢复原草稿；编辑或清空原行动时也保留历史 |
| 完成与待反馈 | 测评／面试未待反馈时，详情按钮“完成并待反馈”直接完成当前行动并更新状态；进展表单选择进入待反馈后保存有同样效果。原来的完成后状态选择弹窗已移除。其他阶段及已待反馈记录仅“完成行动”，不改变求职状态。历史保留原行动与时间，只有新进入待反馈才重置等待起点 |
| 取消行动 | 详情提供独立“取消行动”按钮，取消只清理当前行动、时间和提醒；保留阶段、状态、轮次、等待起点及 Offer 决定，历史明确记录取消而非完成 |
| 返回投递阶段 | 更新面板预填待投递，用户可改为已投递；旧轮次和阶段历史保留 |
| 日期与时间 | 日期必然属于当前行动的截止或预约语义；允许仅日期，需要时补充具体时间。Offer 答复期限按截止处理 |
| 提醒口径 | 今天、本周按行动日期判断；逾期仅包含未完成的截止事项；已过预约采用独立的待更新文案，不混入逾期数量 |
| 等待时长起点 | 以进入已投递或待反馈的时间为起点；重新进入等待状态重新计时，历史中的先前等待记录保留 |
| 筛选口径 | 日期范围指当前下一步行动日期；列数反映当前筛选结果。已归档作为独立查看范围，提供清除筛选入口 |
| 同时刻排序 | 同一行动时间以最近更新优先打破平局；无日期仍置后；切换最近更新则按更新由新到旧排序 |
| 表单错误 | 必填项为空时保留已填内容，字段下显示具体错误并突出首个错误；无需禁止合法的过去日期 |
| 视觉与可读性 | 中文浅色，白卡片、浅灰列；全局主操作使用蓝色，详情主题按上表贯穿主要信息区域，提醒色局部叠加；状态同时有文字，不能只靠颜色传达 |

## 产品主题：下一站 NEXT STOP

用户要求为产品加入创意主题，同时保持详情页原样。按用户最新截图偏好，主界面采用参考图取样的蓝色 `#3468e8`、冷浅灰背景 `#f8f9fc`、白色导航和卡片，以及浅蓝选中背景 `#edf3ff`；路线插画、四站编号、票签缺口与虚线构成视觉识别。保留 JobKANBAN 名称，求职阶段及业务操作不变。

新主题样式限定在主导航与看板容器，详情和表单没有重新设计。岗位详情、Offer、归档详情、编辑、新建和待反馈进展六个面板的单体截图及计算样式，与修改前对照一致。新的看板背景自然会出现在弹窗后方；验证时隔离背景以检查面板本体。主看板另检查 1440／1200 像素宽度，8 项检查通过，证据见 [shell-theme-validation.json](../design/exports/shell-theme-validation.json)。
