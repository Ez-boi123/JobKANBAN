## 交付目标

交付可在个人电脑持续使用的求职管理应用：前端网页、后端接口、SQLite 数据库、启动说明和自动化验收。新建、修改、进展、轮次、行动、Offer 决定及归档均真实保存；刷新浏览器或重启服务不丢失已成功保存的数据。

## 方案选择

使用 React + TypeScript 重建现有界面，复用已确认 CSS，将界面拆分为看板、详情、表单与接口通信组件；使用 Node.js 后端和 SQLite 文件数据库。这样可直接复用已确认设计，单个服务同时提供网页和接口，个人使用无需另行安装数据库服务器。

用户已选择本地单用户版，监听本机地址；具有完整的 React 前端、后端与数据库。云端账号与跨设备同步不在本次范围。

本机 Node.js 为 24.14.0，已验证其内置 SQLite 可用；该接口在本机运行时带实验性提示。数据库访问封装在独立模块，记录运行版本，避免向界面泄露数据库实现。

## 前端与流程

沿用蓝灰看板、四阶段、居中详情及六类详情主题。包含新建与编辑、搜索和组合筛选、两种排序、拖动后的进展确认、多轮记录、完成并待反馈、独立取消行动、Offer 决定和归档恢复。

浏览器启动时读取后端记录，首次正式使用显示空看板。原演示独立保留，示例数据和固定时间不注入正式数据库，演示重置不影响实际记录。

提交期间防止重复操作；后端确认保存后才显示成功。网络或校验失败时保留表单内容、显示具体错误并允许重试。冲突时提示重新读取，避免另一页面的旧数据覆盖新进展。

## 后端与存储

后端提供查询、新建、修改基础资料、更新进展、完成／取消行动、记录 Offer 决定及归档／恢复接口。后端统一校验阶段状态、必填字段、日期类型和结果，不接受浏览器直接替换整份记录或历史。

数据库包含求职记录、轮次与追加式变更历史。每条记录具有稳定标识、版本、创建及更新时间。当前状态改变与历史写入处于同一事务，失败时全部回滚。数据文件保留在独立数据目录，不纳入 Git；启动自动建立或迁移表结构，不清空已有数据。

进展命令保留旧阶段、状态、轮次、行动和日期。完成与取消保持不同语义，跨阶段不推断通过，Offer 决定不发送消息。记录每轮的时间、备注和结果；推进下一轮不会覆盖上一轮。

正式运行使用真实时钟，日期按北京时间解释，只有日期的截止时间在当天结束后才逾期。预约已过标记待更新。测试通过可控时钟验证这些规则。

服务仅提供规定的静态资源和 API，不向浏览器暴露数据库文件。校验输入长度与链接协议；数据访问使用参数化查询。当前本地版不提供无认证的公网访问。

## 验收与交付

主要验收边界为浏览器完整操作：新增记录、刷新后存在、修改行动与进展、检查可见历史、记录 Offer、归档恢复、重启服务后继续读取。还验证保存失败不假报成功、重复操作及多页面冲突。

后端 HTTP 接口补充校验非法状态和事务一致性；不依赖内部函数作为产品测试契约。每个缺口先复现失败再实现，最终运行完整回归、语法／类型检查及规范和规格两轴审查。

提交包含完整源码、启动入口、数据库初始化、测试与运行说明。给出本地网址及明确启动命令，区分真实应用与原演示。代码审查拟以开发前快照为基准，实施结束提交到当前分支。
